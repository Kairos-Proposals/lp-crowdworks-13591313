PROPOSAL FROM KAIROS — hmllp_柳澤研 様

全国で、毎日生まれる法人を。
見つけ、整え、営業リストに変える。

国税庁法人番号公表サイトという「公的な出生届」から、企業のWebサイト・連絡先という「生きた情報」まで。 散らばったデータを自動で辿り、使える形に整える仕組みを、Kairosがゼロから設計します。

法人番号 連携 公式サイト自動特定 生成AIで業種分類 重複排除 / 更新管理 Sheets・CSV出力
Kairos は、Web制作とシステム開発を横断するチームです。本提案は、本募集内容を拝見した上で 構成した、独自の実現プランです。
01 / 案件理解

「公開されている情報」と「使える情報」の間には、
想像より大きな距離がある。

新設法人の情報は、国税庁のサイトに日々公開されています。けれどそこにあるのは法人番号や所在地といった「骨格」だけ。 営業に使えるリストにするには、Webサイトを探し、業種を見極め、連絡先を確かめる——人手に頼れば、件数が増えるほど破綻する作業です。 御社が目指す「横展開できるシステム」には、最初の設計思想がすべてを決めます。

01

公開データは「ある」が、構造化されていない

法人番号公表サイトや各種公開情報は更新頻度・形式がバラバラ。継続収集には、差分検知と正規化の設計が不可欠です。

02

Webサイト特定・業種判定は、人の経験が必要だった領域

社名検索だけでは誤特定が頻発。生成AIによる候補の絞り込みと検証ロジックの両輪が必要です。

03

「全部を一度に」は、実は最もコストが高い

最小構成で早く動かし、精度と項目を段階的に拡張する方が、結果的に運用コストも抑えられます。

04

「自社運用」で終わらせない設計が、将来の資産になる

複数企業・クライアントへの横展開を見据えるなら、収集対象・出力先を差し替え可能な構造にしておく必要があります。

02 / Kairos の提供価値

自動化を「作って終わり」にしない。
運用できる形まで、Kairosが設計します。

VALUE — 01

実用最小構成（MVP）からの段階構築

法人番号データ取得 → 基本情報整理 → スプレッドシート出力という核をまず稼働させ、そこから機能を積み上げます。

VALUE — 02

公開データ × 生成AIのハイブリッド収集

国税庁API等の構造化データと、ChatGPT／Claude／Geminiによる非構造情報（公式サイト・業種・問い合わせ先）の補完を組み合わせます。

VALUE — 03

重複排除・更新管理のデータ基盤

法人番号を主キーとした正規化、取得履歴・更新日・エラーログの管理まで含めた、崩れない運用基盤を構築します。

VALUE — 04

運用コストを抑えた技術選定

Python / GAS / n8n / Make を適材適所で組み合わせ、API従量費・保守工数を抑えながら拡張しやすい構成にします。

VALUE — 05

横展開を前提にした拡張設計

収集対象・出力先・抽出条件を差し替え可能なモジュール構造にし、将来の複数クライアント対応を見据えます。

03 / 進め方

まずは小さく動かし、確かめながら育てる。

すべての機能を初期段階で実装する必要はない、という御社の方針に合わせ、Kairosは4フェーズでの段階的な構築をご提案します。 各フェーズの終わりに動くものを確認いただきながら、次の優先順位を一緒に決めていきます。

Phase 0 ・ 約1週間

要件整理・構成設計

取得項目、情報源、出力形式、運用体制のすり合わせ。推奨システム構成とツール選定をご提示します。

Phase 1 ・ 約2〜3週間

MVP構築：収集の核をつくる

法人番号公表データの定期取得、会社名・所在地・設立時期等の整理、Googleスプレッドシートへの自動出力を実装します。

Phase 2 ・ 約2〜3週間

AI補完：情報を「使える」形に

公式Webサイトの自動特定、業種・事業内容の判定、問い合わせ先・フォームURLの取得を生成AIで補完します。

Phase 3 ・ 継続運用

精度改善・重複排除の高度化

取得履歴・エラー管理の仕組みを整え、定期実行の安定化と精度のチューニングを継続的に行います。

Phase 4 ・ ご相談の上で

横展開：複数対象・複数クライアントへ

収集対象の拡張、他社向けシステムとしての展開など、継続的なご相談の中で次の一手を設計します。

04 / 次の一歩

この仕組みは、最初の1社分では終わりません。

推奨システム構成、概算費用・納期、月額運用費の目安について、 まずは30分ほどお打ち合わせのお時間をいただければ、具体的な形でご提案いたします。
